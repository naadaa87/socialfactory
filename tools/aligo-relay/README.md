# 기존 서울 서버를 이용한 알리고 중계

Cloudflare Pages → HTTPS `relay.naranhistory.com/socialfactory/aligo/send` → 알리고.
나란히 비즈엠·네이버 주문과 같은 서버를 쓰지만 경로와 인증키는 분리합니다.
알리고 API 키·Senderkey·고객 연락처는 디스크에 저장하지 않고 요청만 중계합니다.

## 설치

`install.py`와 `relay.caddy`를 기존 서버의 root 전용 작업 폴더로 옮긴 뒤 `python3 install.py`를 실행합니다.
설치기는 다음을 확인하고 하나라도 다르면 중단합니다.

- 디스크의 설정과 실행 중인 Caddy 설정이 동일함
- 비즈엠·네이버 중계가 실행 중임
- 새 경로를 제외한 Caddy 설정이 이전과 완전히 동일함
- caddy 사용자로 후보 설정 검증 성공
- reload 후 기존 서비스의 PID가 그대로임

설정은 root 전용 폴더에 백업하며 실패 시 원본을 복구합니다. Caddy를 재시작하거나 OS 패키지를 갱신하지 않습니다.
새 키는 서버에서 생성하고 `/etc/caddy/socialfactory-aligo.secret`에 root:root 600으로 저장합니다.
키를 명령행·저장소·채팅·로그에 남기지 마세요. Caddy import에는 root:caddy 640 권한을 사용합니다.
나란히의 초기 설치 스크립트는 Caddyfile을 재작성하므로 이 서버에서 재실행하지 마세요.

## 연결

1. 알리고 ‘신청/인증 → 발송 서버 IP’에 서버의 실제 고정 발신 IPv4 **한 개**를 등록합니다.
2. 소셜팩토리 Cloudflare Pages 운영 환경에 `ALIGO_RELAY_URL=https://relay.naranhistory.com/socialfactory/aligo/send`와 암호화된 `ALIGO_RELAY_SECRET`을 함께 설정합니다.
3. 신규 Pages 배포에서 환경변수가 적용됩니다. 최초 검증은 `ALIGO_TEST_MODE=Y`, `ALIMTALK_ENABLED=0`으로 합니다.
4. 관리자 ‘알리고 연결 시험’에서 알리고 테스트 모드 응답을 확인합니다. 실제 수신 시험과 운영 자동 발송 활성화는 별도입니다.

전용 Bearer 인증과 폼 POST만 허용하며, 목적지는 알리고 발송 API로 고정합니다.
중계 키는 알리고로 전달하지 않고 Caddy의 기본 Authorization 마스킹을 사용합니다.
본문은 32KB로 제한하고 프록시 자동 재시도는 사용하지 않습니다.
소셜팩토리 코드도 허용된 HTTPS URL만 사용하며 설정 누락·403·타임아웃이면 직접 발송으로 우회하지 않습니다.

## 확인과 복구

- 외부에서 비인증 BizM 경로는 403, commerce 경로는 401, 소셜팩토리 경로는 403이어야 합니다.
- 인증된 소셜팩토리 GET·잘못된 Content-Type도 403이어야 합니다.
- 알리고 테스트 모드 성공은 실제 고객 수신 성공과 구분합니다.
- 나란히 보호 검증에는 실제 고객 발송을 사용하지 않습니다. 기존 설정 동일성과 서비스 PID를 확인합니다.
- 되돌릴 때는 Cloudflare에서 중계 변수 두 개를 제거하고 재배포합니다. 직접 발송은 IP 제한으로 실패할 수 있습니다.
- 서버 설정 복구는 백업 Caddyfile을 복원해 검증한 뒤 reload합니다. 그 후 새 import·secret 파일을 제거합니다.
- 서버 장애 시 두 서비스의 중계가 함께 지연될 수 있습니다. 기존 서버 공유에 따른 장애 범위는 남습니다.

## 2026-10-28 설치 확인

기존 서울 서버에 전용 경로를 설치했습니다. 사용 가능 메모리 약 678MB, 루트 디스크 여유 약 14GB를 확인했습니다.
기존 설정은 Caddy가 생성한 그룹 식별자의 번호 차이를 정규화한 뒤 비교했고 경로·인증·대상·순서는 동일했습니다.
Caddy와 네이버 중계의 PID가 유지됐고, 비인증 기존 BizM 403·commerce 401·신규 경로 403을 확인했습니다.
인증된 GET·잘못된 Content-Type도 403, API 키·수신자 없이 testMode=Y만 전송한 요청은 알리고 JSON 응답을 반환했습니다.
전용 Bearer 키가 접근 로그에 없는 것도 서버 내부에서 확인했습니다. 고객 메시지는 발송하지 않았습니다.

알리고 IP 등록은 **30개 한도**로 거절됐습니다. 대표자가 사용하지 않는 기존 IP를 확인한 후 서버 IP 한 개로 교체해야 합니다.
기존 IP 목록은 변경하지 않았습니다. 운영 Pages 중계 변수 연결·main 병합과 테스트 모드 최종 성공은 아직 별도 단계입니다.
