# 소셜팩토리 클라우드 예약 연동

이 Worker는 Cloudflare Browser Run에서 스페이스클라우드 호스트 UI 작업을 수행하고, 공개 예약 가능 시간은 별도 읽기 전용 API로 확인합니다. 노트북이나 매장 PC가 꺼져 있어도 Cloudflare의 예약 실행에서 돌아갑니다. 기존 `integrations/spacecloud-worker`의 방·날짜·고유 표식 검증을 재사용하며 브라우저를 계속 열어 두는 서버는 필요하지 않습니다.

현재 `wrangler.toml`은 소셜팩토리 운영 계정에 연결된 활성 구성입니다. 다른 계정에서 재사용할 때는 먼저 `ENABLED=false`, `ALLOW_WRITES=false`로 바꿔야 합니다. `npm run dry-run`은 원격 리소스를 변경하지 않습니다.

## 비용 확인과 예산

- Workers Free의 Browser Run은 하루 10분이며, 한도 초과 시 새 세션 생성이 429로 거절됩니다. 무료 모드의 자체 예산은 하루 최대 9분입니다.
- Workers Paid는 월 10시간의 브라우저 사용이 포함되고 초과 사용은 시간당 $0.09입니다. Workers 구독은 계정당 최소 월 $5이며, 기존 유료 계정의 포함량을 사용하는 것과 새 구독을 구매하는 것은 구분해야 합니다.
- `CLOUD_PLAN_MODE=paid-included`, `INCLUDED_BUDGET_CONFIRMED=true`는 관리자가 현재 요금제·기존 사용량을 확인한 경우에만 설정합니다. 이 모드의 자체 예산은 하루 최대 90분·최근 32일 최대 2시간입니다. 달력 월 단위로도 2시간을 넘지 않습니다. 일별 한도를 늘려도 월별·이동 기간의 총 사용 한도는 늘어나지 않습니다. Cloudflare의 청구 주기가 매월 1일과 같다고 가정하지 않으며, 이동 기간 제한을 별도로 적용합니다. 나머지 포함량은 여유로 남깁니다.
- 이 예산은 **이 프로그램의 사용량 제한**입니다. Cloudflare 계정 전체에 대한 공급자 과금 상한이 아니며, 계정의 다른 브라우저 프로그램이 소비하는 시간까지 자동 집계하지 않습니다. 다른 사용량이 있다면 포함량을 다시 확인해야 합니다. `ROLLING_32D_BROWSER_BUDGET_MS`, `MONTHLY_BROWSER_BUDGET_MS`의 상한은 각각 7,200,000ms입니다.
- 작업 전 전체 실행시간과 종료 여유분을 D1에서 원자적으로 예약합니다. 종료가 원격에서 확인된 경우만 실제 경과시간과 여유분으로 정산합니다. 종료 여부가 불명확하면 전체 예약분을 유지하고 새 실행을 보류합니다. 빈 작업 큐는 브라우저를 만들지 않으며 예약 예산을 전액 돌려놓습니다.
- 로그인 화면은 5분, 개별 작업은 최대 2분 동안 사용합니다. 종료를 위한 1분 여유분도 먼저 확보합니다. 예산이 부족하면 홈페이지 작업을 임대하기 전에 중단합니다.
- 날짜 경계를 넘겨 사용량을 잘못 계산하지 않도록, 전체 실행·종료 여유분이 UTC 사용량 집계 날짜를 넘는 시점에는 새 브라우저를 시작하지 않습니다. 임대가 만료되었지만 종료 여부가 확인되지 않은 전역 잠금은 재사용하지 않습니다.

공식 근거: [Browser Run 요금](https://developers.cloudflare.com/browser-run/pricing/), [한도와 무료 초과 처리](https://developers.cloudflare.com/browser-run/faq/), [Workers 요금](https://developers.cloudflare.com/workers/platform/pricing/).

## 운영자 배포 순서

1. 올바른 Cloudflare 계정과 현재 요금제·Browser Run 월 사용량을 확인합니다. 비용이 추가되는 업그레이드는 사용자에게 먼저 알립니다.
2. 전용 D1 저장소를 생성하고 `wrangler.toml`의 `STATE_DB` 실제 ID를 연결합니다. `schema.sql`을 실행하거나 첫 제어 요청 시 자동 초기화합니다.
3. `CLOUD_ADMIN_TOKEN`, 홈페이지와 동일한 `SPACECLOUD_WORKER_TOKEN`, 무작위 32자 이상의 `SESSION_ENCRYPTION_KEY`를 Secret으로 설정합니다. 채팅·쿼리 문자열·공개 JS에 넣지 않습니다.
4. 최초 배포에서는 `ENABLED=false`, `ALLOW_WRITES=false`를 유지합니다. 확인한 비용 모드만 설정합니다.
5. `crons=["* * * * *"]`와 `LOGIN_CLEANUP_SCHEDULED=true`를 함께 설정합니다. 로그인 전부터 이 정리 스케줄이 실행되어야 합니다. 작업 비활성 중에도 만료된 자체 브라우저를 종료합니다.
6. 전용 클라우드 브라우저 로그인과 읽기 전용 확인을 완료합니다. 빈 시간대의 등록·해제 종단 검증을 수행한 뒤에만 `ALLOW_WRITES=true`, `ENABLED=true`로 전환합니다.

```sh
npm ci
WRANGLER_LOG_PATH=/private/tmp/spacecloud-cloud.log npm run dry-run
npm test
```

`dry-run`은 배포하지 않습니다. 실제 리소스 생성·Secret 설정·배포는 소유자 계정과 비용을 확인한 운영자가 수행합니다. 운영 구성에는 1분 간격 Cron이 등록되어 있습니다.

## 사용자에게 필요한 로그인

운영자는 인증된 `POST /login/start`로 임시 로그인 화면을 만듭니다. 사용자는 전달받은 비공개 화면에서 **스페이스클라우드 호스트 계정으로 로그인**하고, 운영 화면의 **로그인 저장**을 누르면 됩니다. 비밀번호나 인증번호를 채팅에 보내거나 로컬 Chrome의 쿠키를 복사할 필요가 없습니다.

`POST /login/save`는 해당 클라우드 브라우저에 다시 연결하여 실제 소셜팩토리 호스트 캘린더를 확인한 뒤, **스페이스클라우드 도메인의** 쿠키·localStorage·IndexedDB 상태만 AES-GCM으로 암호화해 D1에 보관합니다. Google·네이버 등 로그인 제공자의 다른 도메인 상태는 보관하지 않습니다. 저장 후 원격 브라우저를 종료합니다. Live View 링크는 세션 접근 권한을 담고 있으므로 로그나 공개 페이지에 남기지 않습니다.

로그인이 만료되거나 Cloudflare 브라우저가 스페이스클라우드에서 차단되면 새 결제를 열지 않고 재로그인을 안내합니다. Cloudflare Browser Run 트래픽은 봇으로 식별되므로, 로그인과 저장 후 복원이 실제로 되는지 검증해야 합니다. [공식 Live View](https://developers.cloudflare.com/browser-run/features/live-view/), [Playwright 저장 상태](https://developers.cloudflare.com/browser-run/playwright/).

`PUBLIC_AVAILABILITY_MODE=public-api-v1`에서는 **호스트 로그인만 필요하며 고객 로그인은 요구하지 않습니다**. 공개 사이트가 사용하는 시간별 `available` 값을 인증정보 없이 읽는 확인기를 명시적으로 선택합니다. 호스트 UI의 고유 표식·시간·다른 예약 검사와 공개 시간 확인은 계속 필수입니다. API 오류·알 수 없는 응답은 확인 성공으로 처리하지 않으며, 실제 등록·해제 시 해당 시간의 값이 바뀌는지 운영 환경에서 확인한 뒤에만 예약을 개방합니다.

이 설정을 생략한 레거시 브라우저 검증 경로는 고객 달력 로그인을 요구합니다. 이는 기존 확인기가 고객 예약 UI의 로그인 제한 경로를 사용한 데 따른 의존성입니다. 호스트와 고객 인증이 반드시 별도라는 사실이나 추가 로그인이 플랫폼 전체에 필수라는 사실이 증명된 것은 아닙니다. 알 수 없는 `PUBLIC_AVAILABILITY_MODE` 값은 레거시 경로로 우회하지 않고 실행을 차단합니다.

호스트 상태는 `spacecloud`, 레거시 고객 달력 상태는 `spacecloud_public` 키로 각각 암호화하여 저장합니다. 공개 API 모드에서는 호스트 컨텍스트만 만들고 고객 프로필을 읽거나 덮어쓰지 않습니다. 레거시 경로에서만 두 상태와 별도 컨텍스트를 요구합니다. 상태 응답의 `public_verification.mode`·`configured`는 선택된 확인 방식의 구성 여부이며 실제 로그인 저장 여부와 구분합니다. `/guest-login/start`, `/guest-login/save`, `/guest-login/cancel` 등 보존한 레거시 제어는 관리자 인증과 기존 5분 유효시간·자동 종료·사용량 제한을 유지합니다.

레거시 고객 로그인 저장은 원래 스페이스클라우드 탭의 인증된 달력을 먼저 확인합니다. 확인된 상태만 별도 암호화 후보로 30분간 보관하고, 새 컨텍스트의 달력 확인이 성공해야 운영용 상태로 승격합니다. 실패하면 원래 로그인 세션을 기존 만료 시각까지 유지하며 만료 시각이나 예산을 연장하지 않습니다. 카카오 팝업이 닫힌 것만으로 저장 성공으로 판단하지 않습니다.

`POST /guest-login/revalidate`는 레거시 후보(없으면 기존 운영용 고객 상태)를 완전히 새 브라우저에서 읽기 전용으로 확인합니다. 예약 큐나 외부 예약을 변경하지 않으며 실패해도 후보와 기존 운영용 상태를 유지합니다. 후보가 있다는 사실만으로 예약을 열 수 없습니다. 레거시 경로는 원본 인증과 새 브라우저 복원을 검증해야 하며, 공개 API 모드는 새 브라우저의 호스트 인증 복원과 공개 시간 데이터의 실제 차단·해제 반영을 검증해야 합니다. 공개 API 모드에 추가 고객 로그인을 요구하지 않습니다. 자동화 테스트 통과는 실제 운영 검증을 대신하지 않습니다.

## 제어 API

공개 `GET /health`에는 서비스 이름과 활성 여부만 나옵니다. 다음 제어 요청은 `Authorization: Bearer CLOUD_ADMIN_TOKEN`이 필요합니다. 브라우저에서 직접 요청한다면 같은 원점만 허용합니다.

| 주소 | 동작 |
| --- | --- |
| `GET /status` | 로그인 저장 여부·자체 사용량·작업 잠금 상태 |
| `POST /login/start` | 5분짜리 전용 로그인 세션·Live View 생성 |
| `POST /login/save` `{login_id}` | 본인 세션의 호스트 로그인 확인·암호화 저장·종료 |
| `POST /login/cancel` `{login_id}` | 본인 임시 로그인 세션 종료 |
| `POST /check` | 저장한 로그인으로 1~5번룸 캘린더 읽기 전용 확인 |
| `POST /run` | 다음 예약 실행에서 처리한다는 `202` 응답만 반환 |
| `POST /maintenance` | 만료된 자체 브라우저 세션 정리 |

`/run`만 홈페이지 연결용 `SPACECLOUD_WORKER_TOKEN`도 허용합니다. 이 토큰으로 로그인 화면·저장 상태·관리 정보에 접근할 수는 없습니다. `/run` HTTP 요청 안에서는 예약을 임대하거나 UI를 조작하지 않습니다. 홈페이지의 요청이 끊겨도 작업이 중간에 종료되지 않도록 실제 쓰기는 Cloudflare Cron에서만 수행합니다.

Cron은 전용 로그인·비용 확인·예산·전역 잠금을 확인한 후 홈페이지 큐의 작업 하나를 임대합니다. 방별 충돌 잠금은 홈페이지 D1에 그대로 유지됩니다. 외부 UI 작업 중 20초마다 임대를 갱신하고, 등록·삭제 직전에도 권한과 시간을 확인합니다. 브라우저 종료를 확인하지 못하면 전역 잠금을 확인 필요 상태로 남깁니다. 기존 예약을 자동 삭제하거나 불명확한 작업을 다시 생성하지 않습니다.

외부 예약 일정은 기존 스페이스클라우드 iCal을 사용합니다. 결제금액은 SPACECLOUD_CLOUD_SALES=true일 때 같은 호스트 로그인을 사용해 정산 예정·완료 화면에서 읽습니다. 평상시 6시간마다 실행하고, 마지막 성공 이후 확인하지 못한 결제일은 기간을 나눠 이어서 처리합니다. 최근 결제일을 겹쳐 확인하고, 오래된 결제일은 하루에 한 구간씩 순회해 늦은 환불도 확인합니다. 실패한 기간은 보존하여 30분 후 다시 시도합니다.

결제 수집은 예약 큐를 임대하거나 스페이스클라우드의 일정을 수정하지 않습니다. 기존 전역 잠금과 브라우저 사용 한도를 공유하며, 예약 작업을 먼저 처리합니다. 모든 페이지와 두 정산 목록을 확인한 결과만 홈페이지의 인증된 수집 API에 전송합니다. Chrome 보조 연결과 동일한 예약번호를 사용해 한 번만 집계합니다. 어드민 매출에서 클라우드 마지막 성공·확인 기간·보류 건을 확인할 수 있습니다. 관리자 인증 POST /sales/check로 기한이 된 수집 또는 실패 건의 재시도를 즉시 실행할 수 있습니다.

운영 전 1~5번룸의 비공개 iCal 연결이 설정되어 있는지 확인해야 합니다.

## 홈페이지 관리자에서 다시 로그인

홈페이지 관리자 → 예약 탭 → 클라우드 예약 연동에서 상태와 사용량을 확인할 수 있습니다. 로그인 만료 시 로그인 다시 연결을 누르고, 5분짜리 비공개 화면에서 호스트 로그인 후 로그인 저장을 누릅니다. Pages의 `CLOUD_ADMIN_TOKEN`은 Worker와 같아야 하며 서버에서만 사용합니다. 고객 예약 공개 여부는 `SPACECLOUD_BOOKING_OPEN`으로 별도 제어합니다.

## 수기 예약의 날짜·룸 변경과 과거 기록 대조

`SPACECLOUD_CLOUD_CALENDAR=true`이면 서버에 저장한 암호화 호스트 인증으로 앱이 사용하는 월별 읽기 전용 API를 직접 조회해 1~5번룸의 수기 일정을 확인합니다. 2026년 10월부터 다음 달 및 iCal에 나타난 가장 먼 예약 월까지 모든 중간 월과 룸을 대조합니다. 수기 일정의 내부 번호·날짜·시각·표시 이름만 저장하며 전화번호·메모·인증 헤더는 저장하거나 로그로 내보내지 않습니다.

전체 조회가 성공한 경우만 한 트랜잭션으로 게시합니다. 기존 iCal·과거 기록·직전 원본 스냅샷에서 보였지만 해당 월의 원본에서 사라진 수기 일정은 별도 제외 기록으로 보존합니다. 이름 추정이나 시간 중복 여부와 관계없이 날짜·룸 이동, 이름 수정, 삭제를 반영하며, 고유 번호가 없는 레거시 이력도 이전 룸·월의 실제 원본으로 대조합니다. 스페이스클라우드의 예약·결제·환불을 수정하거나 삭제하지 않습니다. 어드민 결제 장부도 그대로 유지하며 예약 현황에서만 변경 전 시간의 점유를 제외합니다. 홈페이지가 등록한 `SFWEB:` 시간 확보는 과거 원본 복사본으로 되살리지 않습니다.

평상시 6시간마다 실행하고, 어드민의 **외부 일정 새로 불러오기**는 즉시 전체 대조를 요청하며 처리 중이거나 연결이 끊기면 다음 Cron이 이어서 실행합니다. 어드민에는 요청 대기·대조 중·마지막 성공 시각·재시도 필요 상태가 표시됩니다. 조회 실패·형식 변경·인증 만료·예산 부족 시 마지막 성공 원본을 보존하고 30분 뒤 재시도합니다. 정상 API 조회는 브라우저를 만들거나 브라우저 실행 예산을 예약하지 않습니다. API 인증이 만료되면 공식 토큰 갱신을 한 번 수행하고 암호화 저장합니다. 저장된 프로필이 없거나 앱에서 인증 복원이 필요한 때만 기존 브라우저 한도·최대 2분 실행·자동 종료 정책으로 복원합니다. 전역 잠금은 예약 쓰기 작업과 공유합니다. PC와 Chrome 실행 여부에 의존하지 않습니다.

관리자용 `POST /calendar/check`는 기한이 된 대조를 즉시 실행합니다. 홈페이지 수집용 `/api/internal/spacecloud-calendar`는 기존 Worker 토큰으로만 접근할 수 있으며 완전한 조회 범위, 룸별 상품 번호, iCal 구성 해시, 실행 시각을 검증합니다.
