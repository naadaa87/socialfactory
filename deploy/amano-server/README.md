# 소셜팩토리 아마노 자동 등록

기존 `158.247.232.204`의 `/opt/megaspot-amano` 서비스와 연결된 한아름건물 아마노 계정·잔액을 재사용합니다. 계정·비밀번호를 복사하거나 새로 저장하지 않습니다. 소셜팩토리 서명은 기존 `/etc/caddy/socialfactory-aligo.secret`에서 서버 내부로만 전달합니다. 서버 상태·중지·처리 원장은 `socialfactory-` 이름으로 암호화해 구분하며 한 프로세스의 실행 잠금으로 두 브랜드의 등록이 겹치지 않게 합니다.

- 고객의 실제 결제 승인, 이용일, 전체 차량번호, 차량별 실제 입차가 확인된 건만 주말·공휴일·야간을 포함해 매일 24시간, 1분 간격으로 처리합니다. 과거 소셜팩토리 수동 운영 시간·휴무일은 적용하지 않습니다. 일일권 유효기간은 이용일 당일 23:59까지입니다.
- 무료 1시간을 먼저 확인·적용하고 필요한 유료 시간만 등록합니다. 주문별 최대 원가는 1/2/3시간권 3,000/6,000/9,000원, 일일권 20,000원이며 차량별 결제 원금보다 많이 차감하지 않습니다. 잔액 충전은 하지 않습니다.
- 동일 입차·무료 이력·할인 코드·금액·잔액 차감을 재확인합니다. 환불·정정 문의, 중복 입차, 결과 불명은 확인 필요로 보류하고 임의 재등록하지 않습니다. 실제 등록 확인 뒤에만 완료 상태와 기존 승인 알림톡을 생성합니다.
- 구매 내역은 결제 완료 화면, 회원·휴대폰 인증 비회원 주문 목록, 차량별 알림톡의 통합 결제 링크로 확인합니다.

## 배포

1. `node --test tests/parking-automation.test.mjs tests/amano-reference/*.test.mjs tests/parking.test.mjs`로 서명·이중 실행·실결제·환불·무료 우선·차감 확인·완료 알림을 검사합니다.
2. 서버 모듈·참조 테스트를 임시 디렉터리에 올린 뒤 해당 서버의 Node로 참조 테스트를 실행합니다. `install-socialfactory.py`는 기존 파일 해시와 실행 중 여부를 확인하고 비공개 백업 후 서비스·Caddy를 갱신합니다. 실패하면 기존 파일과 서비스로 복원합니다. 이 단계에서는 소셜팩토리 자동 등록을 켜지 않습니다.
3. `install-24h.py`와 `socialfactory-24h.conf`를 같은 임시 디렉터리에 올려 `python3 install-24h.py`를 실행합니다. 기존 서버는 재시작하지 않고 공유 타이머의 시간 제한만 제거합니다. 기존 설정을 비공개 백업하며 검증 실패 시 원래 일정으로 복원합니다.
4. 사이트 API·관리자·구매 내역 화면을 GitHub/Cloudflare에 배포합니다. 새 D1 설정·처리 잠금 표는 API에서 자동 준비합니다. 기존 주차 주문 표는 다시 이관하지 않습니다.
5. 관리자 **주차권 관리 → 아마노 서버 자동 등록**에서 연결 확인 후 켭니다. 사이트와 서버가 모두 켜져 있어야 신규 처리를 시작합니다. 중지는 사이트 잠금을 먼저 끄므로 서버 연결이 끊겨도 새 등록이 차단됩니다.
6. 운영자 로그인 확인, 서명된 처리 대상 조회, 정기 실행 결과를 검사합니다. 실제 주문이 없으면 ‘처리 0건’을 기록하며 가짜 주문이나 시험 차감을 만들지 않습니다.

기존 메가스팟 계정·활성화 설정·암호화 상태는 유지합니다. 공유 타이머에 `socialfactory-24h.conf` 드롭인을 설치해 매일 24시간 실행하며, 메가스팟 처리 가능 시간은 기존 메가스팟 API 정책을 따릅니다. 한 프로세스의 실행 잠금은 그대로 사용합니다. `systemd-analyze calendar`로 야간·토요일·일요일·공휴일의 다음 실행과 1분 간격을 확인합니다. 등록 실패는 소셜팩토리 관리자에 표시하며, 확인 필요 건은 아마노 실제 내역을 확인한 뒤 처리합니다. 소셜팩토리의 자동 등록 오류·잔액 부족은 기존 알리고 발신번호의 관리자 LMS로 알립니다.

## 관리자 오류 문자

`ALIGO_PARKING_ADMIN_RECEIVERS`의 기존 허용 목록 중 사용자 지정 번호만 `SOCIALFACTORY_PARKING_ADMIN_RECEIVERS`에 설정합니다. 실제 번호는 저장소에 넣지 않습니다. `install-admin-alerts.py --receiver-last4 NNNN`는 허용 목록에서 끝번호가 유일하게 일치하는 수신자만 선택합니다. 기존 실행 파일의 해시·진행 중 등록 여부를 확인하고 비공개 백업 후 아마노 처리기·문자 중계를 갱신합니다. 두 브랜드의 등록 활성화와 24시간 타이머를 검증하고, 실패하면 복원합니다. 설치 과정은 시험 문자나 가짜 등록을 만들지 않습니다.

- 등록 실패는 주문별 1회, 잔액 부족은 한국 날짜별 1회 알립니다. 정상 처리·단순 입차 대기에는 새 문자를 보내지 않습니다.
- 문자에는 소셜팩토리 명칭, 주문번호, 오류 사유(잔액 부족 시 필요액·잔액), 관리자 링크를 넣습니다. 고객 전화번호·구매내역 비밀 토큰은 넣지 않습니다.
- 소셜팩토리 전용 중계 경로는 기존 허용 목록과 소셜팩토리 지정 번호의 교집합, 고정 오류 제목·관리자 링크, 서명·유효시간을 검증합니다. 메가스팟 기존 문자 경로와 수신자는 그대로 유지합니다.
- 오류 원장과 요청 ID를 브랜드별로 구분합니다. 전송 결과 불명은 동일 ID로만 확인하고 중계의 영속 선점으로 중복 발송을 막습니다. 알리고 접수와 실제 전달 성공은 관리자에 별도 표시합니다.
- 등록 처리 중 예외·설정 누락도 알리고, 등록 서버 프로세스가 응답하지 않으면 독립 systemd 주기 실행기가 알립니다. 문자 전송 오류는 완료된 주차 등록을 되돌리지 않습니다.

결제 승인 콜백은 서명된 `process` 요청으로 해당 결제의 아마노 확인을 즉시 시작합니다. 미입차 차량은 매분 정기 실행에서 다시 확인합니다. 실제 입차를 확인한 뒤에만 무료 우선 배정·등록 잠금과 입차 이벤트를 원자적으로 저장합니다.

관리자 결제 문자는 `SOCIALFACTORY_PARKING_PAID_ADMIN_RECEIVERS`의 허용된 번호로 통합 결제당 한 번씩 보냅니다. 기존 오류 알림과 별도의 암호화 원장·요청 ID를 사용합니다. `SOCIALFACTORY_PARKING_PAID_ADMIN_SINCE`에 지정한 한국 날짜의 결제부터 복구하며, 현재 미결제·테스트·부분 또는 전체 환불은 제외합니다. 접수와 실제 전달 성공은 관리자에서 구분합니다.

`install-paid-alerts.py --phase install`은 운영 파일 해시와 처리 잠금을 확인하고 비공개 백업 후 즉시 등록·매분 타이머를 설치합니다. 운영 문자 중계의 다른 배포 기능은 정확한 코드 구간만 확장해 보존합니다. 사이트 배포 후 `--phase enable --since YYYY-MM-DD --receiver-last4 NNNN ...`로 결제 문자를 활성화합니다. 활성화 전 서명된 결제 API를 확인합니다.
