# 소셜팩토리 아마노 자동 등록

기존 `158.247.232.204`의 `/opt/megaspot-amano` 서비스와 연결된 한아름건물 아마노 계정·잔액을 재사용합니다. 계정·비밀번호를 복사하거나 새로 저장하지 않습니다. 소셜팩토리 서명은 기존 `/etc/caddy/socialfactory-aligo.secret`에서 서버 내부로만 전달합니다. 서버 상태·중지·처리 원장은 `socialfactory-` 이름으로 암호화해 구분하며 한 프로세스의 실행 잠금으로 두 브랜드의 등록이 겹치지 않게 합니다.

- 고객의 실제 결제 승인, 이용일, 전체 차량번호, 차량별 입차 요청이 확인된 건만 주말·공휴일·야간을 포함해 매일 24시간, 5분 간격으로 처리합니다. 과거 소셜팩토리 수동 운영 시간·휴무일은 적용하지 않습니다. 일일권 유효기간은 이용일 당일 23:59까지입니다.
- 무료 1시간을 먼저 확인·적용하고 필요한 유료 시간만 등록합니다. 주문별 최대 원가는 1/2/3시간권 3,000/6,000/9,000원, 일일권 20,000원이며 차량별 결제 원금보다 많이 차감하지 않습니다. 잔액 충전은 하지 않습니다.
- 동일 입차·무료 이력·할인 코드·금액·잔액 차감을 재확인합니다. 환불·정정 문의, 중복 입차, 결과 불명은 확인 필요로 보류하고 임의 재등록하지 않습니다. 실제 등록 확인 뒤에만 완료 상태와 기존 승인 알림톡을 생성합니다.
- 구매 내역은 결제 완료 화면, 회원·휴대폰 인증 비회원 주문 목록, 차량별 알림톡의 통합 결제 링크로 확인합니다.

## 배포

1. `node --test tests/parking-automation.test.mjs tests/amano-reference/*.test.mjs tests/parking.test.mjs`로 서명·이중 실행·실결제·환불·무료 우선·차감 확인·완료 알림을 검사합니다.
2. 서버 모듈·참조 테스트를 임시 디렉터리에 올린 뒤 해당 서버의 Node로 참조 테스트를 실행합니다. `install-socialfactory.py`는 기존 파일 해시와 실행 중 여부를 확인하고 비공개 백업 후 서비스·Caddy를 갱신합니다. 실패하면 기존 파일과 서비스로 복원합니다. 이 단계에서는 소셜팩토리 자동 등록을 켜지 않습니다.
3. `install-24h.py`와 `socialfactory-24h.conf`를 같은 임시 디렉터리에 올려 `python3 install-24h.py`를 실행합니다. 기존 서버는 재시작하지 않고 공유 타이머의 시간 제한만 제거합니다. 기존 설정을 비공개 백업하며 검증 실패 시 원래 일정으로 복원합니다.
4. 사이트 API·관리자·구매 내역 화면을 GitHub/Cloudflare에 배포합니다. 새 D1 설정·처리 잠금 표는 API에서 자동 준비합니다. 기존 주차 주문 표는 다시 이관하지 않습니다.
5. 관리자 **주차권 관리 → 아마노 서버 자동 등록**에서 연결 확인 후 켭니다. 사이트와 서버가 모두 켜져 있어야 신규 처리를 시작합니다. 중지는 사이트 잠금을 먼저 끄므로 서버 연결이 끊겨도 새 등록이 차단됩니다.
6. 운영자 로그인 확인, 서명된 처리 대상 조회, 정기 실행 결과를 검사합니다. 실제 주문이 없으면 ‘처리 0건’을 기록하며 가짜 주문이나 시험 차감을 만들지 않습니다.

기존 메가스팟 계정·활성화 설정·암호화 상태는 유지합니다. 공유 타이머에 `socialfactory-24h.conf` 드롭인을 설치해 매일 24시간 실행하며, 메가스팟 처리 가능 시간은 기존 메가스팟 API 정책을 따릅니다. 한 프로세스의 실행 잠금은 그대로 사용합니다. `systemd-analyze calendar`로 야간·토요일·일요일·공휴일의 다음 실행과 5분 간격을 확인합니다. 등록 실패는 소셜팩토리 관리자에 표시하며, 확인 필요 건은 아마노 실제 내역을 확인한 뒤 처리합니다. 소셜팩토리의 새 관리자 문자 발송은 추가하지 않습니다.
