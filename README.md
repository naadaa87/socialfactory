# 소셜팩토리 홈페이지 (SOCIAL FACTORY)

2015년 홍대에서 시작한 모임공간 소셜팩토리의 공식 홈페이지입니다. 현재 공간은 소셜팩토리 건대(서울 광진구 화양동 10-1 한아름건물 4층)입니다.
빌드 과정이 없는 정적 사이트라 GitHub에 올리고 Cloudflare Pages에 연결하면 바로 배포됩니다.

## 스페이스클라우드 예약 시간표 연결

- 어드민 **설정 상태 → 스페이스클라우드 예약 연결**에 룸별 호스트센터의 iCal 내보내기 URL을 저장합니다. 링크는 서버에서 암호화해 D1에 보관하며 화면이나 공개 설정 파일에 다시 노출하지 않습니다.
- `SESSION_SECRET`(없으면 `ADMIN_KEY`)으로 연결 정보를 암호화합니다. 사용한 비밀값을 바꾼 뒤 연결을 읽지 못하면 룸별 URL을 다시 입력해야 합니다.
- 대시보드 · 예약 현황 · 일자별 예약을 열 때 불러오고, 화면이 열려 있는 동안 5분마다 확인합니다. **외부 일정 새로 불러오기**는 캐시와 관계없이 재확인합니다. 어드민이 닫혀 있을 때 실행하는 별도 예약 작업은 없습니다.
- 일정은 별도 `spacecloud_calendar_cache`에 룸별 스냅샷으로 보관합니다. 고유번호와 날짜로 중복을 막고 정상 피드에서 사라진 일정은 시간표에서 제외합니다. 조회 실패 · 잘못된 피드면 마지막 정상 스냅샷을 유지하고 오류를 표시합니다. 스페이스클라우드 쪽 피드 갱신 지연은 별개입니다.
- 날짜 · 시간 · 제목 · 원본 링크만 표시합니다. 외부 일정은 읽기 전용이며 예약자 · 연락처 · 인원 · 결제 정보를 추정하거나 매출에 넣지 않습니다. 수정·취소는 호스트센터에서 진행합니다. 같은 시간에 수동 등록한 스페이스클라우드 예약이 있으면 시간표에는 수동 예약을 우선 표시합니다.
- 시간은 한국 시간 기준으로 변환하며 자정을 넘는 일정은 날짜별로 나눠 표시합니다. 반복 규칙이 든 피드는 확장 지원 전까지 실패로 처리해 이전 일정을 유지합니다.
- 검증: `node --test tests/spacecloud*.test.mjs`로 시간 변환, 중복·오류 처리, 암호화, 관리자 인증, 매출 제외, 화면 표시를 검사합니다.
- 선택 사항: 서버의 `SPACECLOUD_ICAL_FEEDS` 비밀값에 `r1`~`r5` → URL JSON을 지정할 수도 있습니다. 어드민에서 저장한 연결이 우선합니다. 피드 URL은 GitHub나 클라이언트 JS에 넣지 않습니다.

## 1. 배포하기 (브라우저만으로 가능)

### GitHub에 올리기
1. github.com 에 로그인 → 오른쪽 위 **+** → **New repository**
2. Repository name: `socialfactory`, **Public**, 나머지는 그대로 두고 **Create repository**
3. 만들어진 빈 저장소 화면에서 **uploading an existing file** 링크 클릭
4. 이 압축을 푼 폴더 안의 **모든 파일과 폴더**를 드래그해서 올립니다
   (`css`, `js`, `images`, `fonts`, `functions` 폴더째로 올리면 됩니다. `_headers`처럼 밑줄로 시작하는 파일도 꼭 포함)
   GitHub는 한 번에 100개 파일까지만 받으므로, 전체 파일 수가 많다고 나오면 나눠 올립니다.

영상을 바꾸려면 네 파일을 같은 이름으로 덮어쓰고, 첫 장면 이미지(`images/hero/brand-poster.webp`, `brand-poster-sm.webp`)도 새 영상의 첫 장면으로 바꿔 주세요. GitHub 웹 업로드는 파일 하나당 25MB까지라 영상은 10MB 이하로 줄여 올리는 것이 좋습니다.

### 3D 안내
`tour.html` 에 3D 실행 코드가, `images/tour/` 에 참고 이미지가 있습니다. 공간 페이지에서 같은 자리에 끼워 보거나 새 창으로 엽니다. 방을 고르면 그 방의 사진·이용 조건과 문의로 바로 가는 링크가 나옵니다. 새 3D 파일을 받으면 같은 방식으로 이미지를 분리해 넣어야 하므로, 교체가 필요하면 제작자에게 요청하는 편이 빠릅니다.

### 평면도
공간 페이지의 평면도는 `space.html` 안에 그림(SVG)으로 들어 있습니다. 도면에 적힌 치수와 높이만 표기했고, 도면에 없는 높이는 '미기재'로 두었습니다.

## 3. 문의 접수 · 회원 기능 켜기

문의 폼과 회원 기능(이메일 가입 · 마이페이지)은 Cloudflare의 무료 데이터베이스 **D1** 에 저장됩니다. 카카오 로그인은 나중에 붙이기로 하고 지금은 넣지 않았습니다. 모든 설정은 브라우저(Cloudflare 대시보드)에서 할 수 있습니다.

### 3-1. 데이터베이스 만들기 (처음 한 번)
1. dash.cloudflare.com → 왼쪽 메뉴 **Storage & databases** → **D1 SQL database** → **Create Database** → 이름 `socialfactory-db` → **Create**
2. 만든 데이터베이스 → **Console** 탭 → 저장소의 `schema.sql` 파일 내용 전체를 복사해 붙여 넣고 **Execute**
   - 예전에 문의 표(inquiries)를 이미 만들어 쓰고 있었다면 `schema.sql` 대신 `schema-upgrade-members.sql` 을 실행합니다 (기존 문의는 그대로 남습니다). 회원 표까지 이미 있다면 `schema-upgrade-orders.sql` 만 실행합니다 (4-1).
3. **Workers & Pages** → 소셜팩토리 Pages 프로젝트 → **Settings** → **Bindings** → **Add** → **D1 database** → Variable name `DB`, D1 database 는 위에서 만든 `socialfactory-db` → **Save**

### 3-2. 비밀 값 넣기
같은 프로젝트 → **Settings** → **Variables and Secrets** → **Add** 로 하나씩 넣습니다. 종류는 **Secret(암호화)** 으로 고릅니다.

| 이름 | 값 | 용도 |
| --- | --- | --- |
| `ADMIN_KEY` | 영문 · 숫자를 섞은 30자 이상 아무 문자열 | 관리 화면(`/admin`) 열쇠. 남에게 알려 주지 않습니다 |
| `SESSION_SECRET` | 영문 · 숫자를 섞은 40자 이상 아무 문자열 (ADMIN_KEY 와 다르게) | 로그인 쿠키 · 주문 조회 링크 서명 |
| `IP_SALT` | 아무 문자열 | 스팸 방지용 IP 변환에 섞는 값 |
| `NOTIFY_WEBHOOK` | (선택) Discord · Slack 웹후크 주소 (3-4) | 새 문의 · 결제 완료 알림 |

결제(KG이니시스) 관련 값은 4-2 에 따로 있습니다.

### 3-3. 다시 배포하고 확인
1. **Deployments** → 가장 위 배포 오른쪽 **⋯** → **Retry deployment** (바인딩과 비밀 값은 새 배포부터 적용됩니다)
2. 홈페이지 문의 폼으로 시험 문의를 1건 보내 접수번호(SF-…)가 나오는지 확인합니다.
3. `https://socialfactory.co.kr/admin` 에서 ADMIN_KEY 를 관리자 비밀번호로 넣고 **로그인** → 왼쪽 **문의** 메뉴에 방금 문의가 보이면 끝입니다. **설정 상태** 메뉴에서 빠진 설정이 있는지도 한눈에 볼 수 있습니다. 상태(새 문의 · 진행 중 · 처리 완료)를 바꾸면 회원의 마이페이지에도 '접수 · 상담 중 · 완료'로 바로 보입니다.

### 3-4. (선택) 새 문의를 휴대폰으로 알림 받기 — Discord 예시
1. Discord 앱에서 내 서버를 하나 만들고, 알림 받을 채널 옆 톱니바퀴(채널 편집) → **연동** → **웹후크** → **새 웹후크** → **웹후크 URL 복사**
2. 3-2 의 `NOTIFY_WEBHOOK` 에 붙여 넣고 다시 배포합니다. Slack 의 Incoming Webhook 주소도 그대로 쓸 수 있습니다.
3. 알림 전송 결과는 관리 화면 문의 메뉴의 '알림' 칸에 sent / failed 로 남습니다. 결제가 완료될 때도 같은 주소로 알림이 갑니다.

### 3-5. 메뉴에 '로그인' 보이게 하기
`js/site-config.js` 의 `members: { enabled: false }` 를 `true` 로 바꾸고 Commit 합니다. 데이터베이스 연결(3-1~3-3)을 마친 뒤에 켜 주세요. 켜면 메뉴 · 푸터 · 주문서 · 주문 완료 화면에 로그인 · 마이페이지 링크가 보입니다. 켜기 전에도 `/login`, `/signup` 주소는 열리지만 "회원 기능을 준비하고 있습니다"라고 안내합니다.

### 3-6. 운영할 때
- **비밀번호를 잊은 회원**: 카카오톡 문의채널로 가입 이메일과 이름을 받아 확인한 뒤, 관리 화면 **회원** 메뉴 → **임시 비밀번호** → 나온 값을 회원에게 알려 줍니다. 회원은 로그인하면 새 비밀번호로 바꾸라는 안내를 받습니다.
- **소식 · 혜택 수신 명단**: 회원 메뉴 → '소식 수신 동의만' 체크 → **CSV 내려받기**. 광고성 정보는 동의한 회원에게만 보내고, 「정보통신망법」에 따라 동의한 날부터 2년마다 수신 동의 여부를 다시 알려야 합니다.
- **이용 정지 · 삭제**: 회원 메뉴의 버튼으로 처리합니다. 회원이 직접 탈퇴하면 회원 정보는 바로 지워지고, 남긴 문의는 보관 기간까지 회원과 분리해 남습니다.
- **보관 기간이 지난 문의 정리**: 관리 화면에서 CSV 로 내려받아 둘 것을 정리한 뒤 D1 Console 에서 `DELETE FROM inquiries WHERE created_at < '2026-04-01';` 처럼 삭제합니다.

### 3-7. 개인정보 처리방침 · 이용약관
- `privacy.html`(개인정보 처리방침), `terms.html`(이용약관)이 푸터에 연결되어 있습니다. 운영 법인명은 `site-config.js` 의 `company.name` 을 채우면 두 문서에 자동으로 들어갑니다(비어 있으면 '소셜팩토리').
- 개인정보 보호책임자는 '최시준 (대표)', 연락처는 `contact.email` · 카카오톡 문의채널로 적혀 있습니다. 담당자가 바뀌면 `privacy.html` 7번을 고쳐 주세요.
- 새 문의 알림(Discord · Slack 등)을 쓰면 처리방침 3번 '운영자 알림 메신저' 칸에 실제 서비스 이름을 적어 두는 것이 좋습니다.

### 3-8. 관리자 화면에서 예약 · 매출 관리 (2026-10-19)
메가스팟 관리자 화면과 같은 구성입니다. `https://socialfactory.co.kr/admin` 에 ADMIN_KEY 로 로그인합니다.

- **로그인**: 비밀번호는 서버에서만 확인하고, 브라우저에는 다시 읽을 수 없는 로그인 쿠키만 남습니다. 기본 12시간, '7일 동안 로그인 유지'를 고르면 7일. 공용 PC에서는 쓰지 말고 다 쓰면 **로그아웃** 을 누릅니다. 같은 곳에서 15분 안에 8번 틀리면 15분 동안 막힙니다. Cloudflare 에서 ADMIN_KEY 를 바꾸면 모든 기기에서 로그아웃됩니다.
- **표 자동 준비**: 예약 · 관리자 로그인 표(reservations · admin_sessions)는 처음 로그인할 때 자동으로 만들어집니다. D1 콘솔에서 따로 실행할 SQL 은 없습니다.
- **예약 등록** (왼쪽 위 **+ 예약 등록**, 또는 예약 현황 시간표의 빈 칸 누르기, 또는 문의 목록의 **예약 등록**)
  - 공간(1~5번룸 · 코워킹 · 독립사무실 · 기타), 이용일, 시작 · 종료를 **30분 단위**로 고릅니다. 1시간 · 2시간 · 3시간처럼 바로 고르는 버튼도 있고, 자정을 넘기면 '익일 02:00'처럼 다음 날까지 이어서 등록됩니다 (한 번에 최대 24시간).
  - 1~5번룸은 `js/site-config.js` 의 요금표(평일 · 주말 · 공휴일, 오전 · 심야 / 오후 · 저녁)로 금액이 자동 계산됩니다. 30분은 시간 요금의 절반입니다. 할인했거나 스페이스클라우드 판매가가 다르면 결제 금액만 고치고 금액 메모에 이유를 적습니다.
  - **결제수단** 5가지 중 하나를 꼭 고릅니다: 계좌이체(블랭크) · 계좌이체(별도) · 스페이스클라우드 · 카드결제(오프라인) · 카드결제(온라인). 입금 전이면 **결제 전(입금 대기)** 으로 등록해 두고, 입금되면 **결제 확인** 을 누릅니다.
  - 같은 룸 · 같은 시간에 예약이 있으면 등록 전에 알려 줍니다. 정말 함께 받는 경우에만 **겹쳐도 등록** 을 누릅니다.
- **예약 상세**: 예약을 누르면 열립니다. 수정, 고객 안내문 복사(카카오톡 · 문자에 붙여 넣기), 결제 완료 처리, **취소 · 환불**(환불 규정에 맞는 금액을 자동으로 제안 — 실제로 돌려준 금액을 적습니다), 취소한 예약 복원, 잘못 등록한 예약 삭제를 할 수 있습니다.
- **예약 현황**: 일간은 1~5번룸 시간표, 월간은 달력입니다. 파란색은 결제 완료, 노란색은 결제 전입니다.
- **일자별 예약**: 기간 · 공간 · 결제수단 · 결제 상태로 골라 보고 **CSV 내려받기** · **인쇄** 를 할 수 있습니다.
- **매출**: 누적 총매출, 올해 · 이번 달 · 지난달 매출, 미수금(결제 전), 결제수단별 합계, 월별 · 결제수단별 표, 공간별 · 예약 경로별 매출을 봅니다. **이용일 기준** 과 **결제일 기준** 을 바꿔 볼 수 있고, 홈페이지에서 결제된 이용권(KG이니시스, 테스트 결제 제외)을 함께 더할지 고를 수 있습니다. 표의 월을 누르면 그 달 예약 목록이 열립니다.
- 매출 계산: 결제 완료 · 환불 예약의 (결제 금액 − 환불 금액)을 더합니다. 결제 전 예약은 매출이 아니라 미수금으로 셉니다. 취소했어도 환불하지 않은 금액(취소 수수료)은 매출로 남습니다.
- 공휴일이 요금 계산에 들어가려면 `pricing.holidays` 에 날짜가 있어야 합니다. 2028년 공휴일은 2027년 안에 추가해 주세요.

D1 을 연결하지 않으면 문의 폼은 "접수되지 않았습니다"를 보여 주고 `contact.email` 이 있을 때만 메일 앱으로 보내는 길을 안내합니다. 둘 다 준비되지 않았다면 `inquiry.enabled: false` 로 폼을 닫아 두세요.

저장 방식: 비밀번호는 PBKDF2 로 되돌릴 수 없게 바꿔 저장하고, 로그인 유지 토큰도 해시만 저장합니다. 원본 IP와 브라우저 정보(User-Agent)는 저장하지 않습니다. 다른 사이트에서 대신 보내는 요청은 서버에서 거부하고, 로그인 실패가 반복되면 15분 동안 막습니다.

## 4. 이용권 온라인 결제 (KG이니시스)

코워킹 이용권 · 사물함 · 노트북 대여를 홈페이지에서 바로 결제하는 기능입니다. 결제는 KG이니시스 표준결제(PC 결제창 · 모바일 결제)로 처리하고, 주문은 D1 의 `orders` 표에 저장됩니다. 카드 번호는 저희 서버를 거치지 않습니다.

### 4-0. KG이니시스가 요구한 5가지 — 홈페이지에 들어 있는 위치
| 요구 항목 | 홈페이지 반영 |
| --- | --- |
| ① 실제 판매 가능 상품 3~5개 | `/shop` 에 5개: 코워킹 2시간권 · 데이패스 · 월간 정기권 · 개인 사물함(1개월) · 노트북 대여(1일). 상품 내용은 `functions/_lib/products.js` |
| ② 상품 가격 등록 (품절 · 0원 · 임의 가격 불가) | 4,000 / 6,000 / 99,000 / 10,000 / 10,000원 — 이용 요금 페이지의 코워킹 요금과 같은 값 |
| ③ 상세페이지에 배송 기간 · 교환 · 환불 정책 | 상품 상세(`/product/상품id`) 아래 '발급 · 교환 · 환불 안내', `/shop#policy`, 주문서 동의 항목, 이용약관 7조 |
| ④ 메인 하단에 사업자등록증과 같은 정보 | 모든 페이지 푸터 '사업자 정보' — 상호 · 대표자 · 사업자등록번호 · 주소 · 연락처 (`js/site-config.js` 의 `company`) |
| ⑤ 회원만 구매 가능하면 테스트 ID/PW 제공 | 비회원도 구매할 수 있게 만들어 테스트 계정이 필수는 아닙니다. 심사 담당자가 원하면 `/signup` 에서 계정을 하나 만들어 알려 주면 됩니다 |

심사 신청서에는 상품 페이지 주소 `https://socialfactory.co.kr/shop`, 상품 상세 예시 `https://socialfactory.co.kr/product/cowork-day` 를 적으면 됩니다.

### 4-1. 주문 표 만들기 (처음 한 번)
D1 → `socialfactory-db` → **Console** 에서 `schema-upgrade-orders.sql` 내용을 실행합니다. (3-1 에서 `schema.sql` 전체를 새로 실행했다면 이미 들어 있습니다.) 관리자 화면 **설정 상태** 메뉴에서 '주문 표 (orders)' 가 ✓ 로 바뀌면 됩니다.

### 4-2. 결제 키 넣기
KG이니시스 가입이 끝나면 **가맹점관리자(iniweb.inicis.com)** → 상점정보 → 결제수단 관리 · 웹결제 Sign Key 에서 값을 확인할 수 있습니다. 심사 기간에는 KG이니시스 담당자가 준 **테스트 상점 아이디** 를 넣어 두고, 심사가 끝나면 실제 값으로 바꿉니다.

| 이름 | 값 | 비고 |
| --- | --- | --- |
| `INICIS_MID` | 상점 아이디 (예: `INIpayTest` — 공개 테스트 MID) | 없으면 상품은 보이고 결제 버튼 대신 '결제 준비 중' 안내 |
| `INICIS_SIGN_KEY` | 웹결제 Sign Key (테스트 MID 는 `SU5JTElURV9UUklQTEVERVNfS0VZU1RS`) | PC 결제창 서명 |
| `INICIS_MOBILE_HASH_KEY` | 모바일 결제 Hash Key (테스트 MID 는 `3CB8183A4BE283555ACC8363C0360223`) | 없으면 휴대폰에서도 PC 결제창을 씁니다 (동작에는 문제 없음) |
| `INICIS_TEST` | `1` | 화면에 '테스트 결제' 표시. 실제 MID 로 바꿀 때 이 값을 **삭제** |

테스트 값은 KG이니시스가 공개한 샘플 값이라 담당자에게 한 번 확인해 주세요. 값을 넣거나 바꾼 뒤에는 **Deployments → Retry deployment** 로 다시 배포해야 적용됩니다.

### 4-3. 결제 확인
1. `/shop` → 상품 하나 → **구매하기** → 주문서에서 이름 · 휴대폰 번호 적고 동의 체크 → **결제하기** → KG이니시스 결제창이 뜨면 연결이 된 것입니다.
2. 테스트 MID 로 결제하면 실제로 돈이 나가지 않고, 주문 완료 화면과 관리자 화면 **주문 · 결제** 메뉴에 '테스트' 표시가 붙습니다. 테스트 결제는 대시보드 매출에서 빠집니다.
3. 심사 통과 후 실제 MID · Sign Key 로 바꾸고 `INICIS_TEST` 를 지운 뒤, 1,000원 상품으로 한 번 실제 결제 → 가맹점관리자에서 취소까지 해 보면 끝입니다.

### 4-4. 운영할 때
- **입실 안내**: 결제가 들어오면 알림(3-4) 또는 관리자 화면 **주문 · 결제** 메뉴에서 보고, 구매자 번호로 1영업일 안에 출입 방법을 문자로 보냅니다. 처리한 주문은 상태를 **이용 완료** 로 바꾸고 운영 메모에 적어 둡니다.
- **환불**: 고객 요청이 오면 상태를 **환불 요청** 으로 → 가맹점관리자 → 거래내역에서 같은 주문번호(TID)를 찾아 규정 금액대로 전체 · 부분 취소 → 상태를 **환불 완료** 로. 홈페이지에 적힌 규정은 `functions/_lib/products.js` 의 `POLICY` 에 있습니다 (7일 안 미사용 전액, 이후 90%, 정기권 · 사물함은 시작 전 전액 · 시작 후 일할 차감 후 10% 공제, 2시간권 · 데이패스는 사용 후 불가, 노트북은 전날까지 전액).
- **상품 · 가격 바꾸기**: GitHub 에서 `functions/_lib/products.js` 만 고치고 Commit. 상품 페이지 · 주문서 · 결제 금액 검증이 모두 이 파일을 봅니다. 가격은 0원이나 빈값으로 두지 마세요.
- **통신판매업 신고**: 온라인 판매를 계속하려면 관할 구청(또는 정부24)에 통신판매업 신고를 하고, 받은 신고번호를 `js/site-config.js` 의 `company.mailOrderNo` 에 넣습니다. 넣으면 푸터와 판매자 정보에 자동으로 표시됩니다 (비어 있으면 그 줄은 숨겨집니다).
- **주문 기록 보관**: 전자상거래법에 따라 결제 · 공급 기록은 5년 보관합니다. 관리자 화면에서 CSV 로 내려받아 둘 수 있습니다.

## 4-5. 토스프론트 이용권 (현장 무인 결제 → 고객 · 이용권 자동 등록)

매장 토스프론트에서 고객이 **이용권 선택 → 휴대폰 번호 → 개인정보 안내 동의 → 카드 결제**를 하면, 이 홈페이지 서버가 휴대폰 번호로 고객을 찾거나 만들고 이용권을 자동으로 발급합니다. 관리자 화면 **고객 · 이용권** 메뉴에서 이용 중 · 만료 예정 · 결제 · 알림톡을 봅니다.

- **이용 기간**: 결제한 시각부터 시작. 2시간권 2시간, 1일권 24시간, 15일권 15일, 1개월 · 3개월권은 '다음 달(3개월 뒤) 같은 날 같은 시각'(그 날이 없는 달은 그 달 마지막 날)까지.
- **이어 붙이기**: 이용 중인 고객이 또 사면 지금 이용권이 끝나는 시각부터 시작합니다 (좌석 이용권끼리는 종류가 달라도 이어 붙음).
- **중복 발급 방지**: 결제 1건 = 이용권 1장. 같은 결제 결과가 여러 번 와도(재시도 · 응답 유실 후 재확인) 1장만 생깁니다.
- **상품 · 가격**: `functions/_lib/kiosk-products.js` 만 고칩니다. 홈페이지 온라인 판매 상품(`products.js`)과는 따로입니다.
- **카드 환불(전액)**: 플러그인 결제는 토스 POS 에 남지 않아 POS 에서 취소할 수 없습니다. 결제한 그 프론트에서 이용권 고르기 화면 오른쪽 위 **관리** → 직원 비밀번호(`KIOSK_STAFF_PIN`) → 최근 30일 결제 → **결제 취소**. 카드 승인 취소와 함께 이용권 취소 · 환불 기록이 자동으로 됩니다 (뒤에 이어 붙은 이용권은 앞당겨짐).
- **부분 환불 · 다른 방법으로 환불**: 관리자 화면 이용권 목록의 **취소**로 환불 금액만 기록합니다.
- **현금**: 무인 매장이라 프론트 결제창에서 현금은 뺐습니다.
- **프론트 밖에서 판 이용권**(POS · 계좌이체 등)은 **+ 이용권 직접 발급**으로 같은 장부에 넣습니다.

### 어드민에서 프론트 화면 선택하기

- **고객 · 이용권 → 프론트 화면**에서 분류 선택 화면과 상품 선택 화면을 각각 **목록형 / 그리드형**으로 선택합니다. 운영 D1에 등록된 판매 중 상품·카테고리·업로드 이미지로 구성 미리보기를 제공하며, 분류를 눌러 다음 상품 화면도 볼 수 있습니다. 미리보기에서는 결제하지 않습니다.
- **선택한 화면 저장**을 누르기 전에는 매장에 반영되지 않습니다. **저장한 설정으로**는 저장 전 변경만 되돌립니다. 저장에 실패해도 선택은 유지되어 다시 시도할 수 있습니다.
- 설정은 D1의 `kiosk_ui_settings` 표에 저장합니다(없으면 API가 자동 생성). 관리자 API `/api/admin/kiosk-ui`의 GET·PUT은 관리자 인증이 필요합니다. 기본값은 현재와 같은 목록형·목록형입니다.
- `toss-front-plugin/ui.js`가 어드민 미리보기와 실제 플러그인의 공통 화면 모델입니다. 그리드는 공개 SDK 스펙의 `id`, `title`, `onClick`을 사용하며, 상품명과 가격을 제목에 함께 표시합니다. 미리보기의 글자 크기·간격·그리드 배치는 구성 예시이며 실제 단말기에서 최종 확인합니다. 열 수나 상단 카테고리 탭을 임의로 설정하는 기능은 제공하지 않습니다.
- 이 기능을 적용하려면 **서버·관리자 파일과 새 플러그인 번들(`ui.js` 포함)을 최초 한 번 배포**해야 합니다. 이후에는 어드민 저장만으로 변경할 수 있습니다. 플러그인은 다음 **이용권 구매** 진입 시 `/api/kiosk/products`에서 최신 화면 설정을 읽고, 구매 도중이나 뒤로가기에서는 같은 구성을 유지합니다. 설정은 이 서버에 연결된 모든 프론트에 적용됩니다.
- 그리드 API가 없는 구형 SDK에서는 목록형으로 표시해 구매를 계속할 수 있습니다. 새 설정이 반영되지 않으면 단말기 플러그인 버전과 `ui.js` 포함 여부부터 확인합니다.
- 검증: `node --test tests/kiosk-ui.test.mjs` (설정 저장·인증·지원 범위 검증·구매 도중 구성 유지·SDK 호환성).

### 켜는 순서 (토스 확인 · 승인 후)
1. 토스플레이스 개발자센터(developers.tossplace.com)에 플러그인(유형 '토스프론트')을 등록하고, **ACL** 에 이 홈페이지 주소(`https://socialfactory.co.kr`)를 넣습니다.
2. `toss-front-plugin` 폴더 **안의 파일들**(index.html · app.js · ui.js · config.js · images)을 ZIP 으로 묶어 개발 배포로 올리고, **테스트 단말기**에서 시험합니다. (운영 중인 프론트는 건드리지 않습니다. 카드 시험 결제는 실제 승인이 나므로 바로 취소합니다.)
3. Cloudflare Pages → Settings → Variables and Secrets 에 아래 값을 넣고 다시 배포합니다.
   | 이름 | 값 | 설명 |
   | --- | --- | --- |
   | `KIOSK_TEST` | `1` | 시험하는 동안만. 이 동안의 프론트 결제는 '테스트'로 표시되고 매출에서 빠집니다. 운영 전환 때 지웁니다. |
   | `KIOSK_ORIGINS` | (선택) | 플러그인이 열리는 주소를 알게 되면 쉼표로 적어 그 주소만 허용합니다. 비워 두면 모두 허용(단말기 토큰으로만 인증). |
   | `CRON_KEY` | 긴 무작위 문자열 (Secret) | 알림 발송기(Worker)가 서버를 부를 때 쓰는 비밀 값 |
   | `KIOSK_STAFF_PIN` | 숫자 4~8자리 (Secret) | 프론트 이용권 고르기 화면 오른쪽 위 **관리** → 카드 결제 취소에 쓰는 직원 비밀번호 |
4. 관리자 화면 **고객 · 이용권 → 단말기 → + 단말기 연결 코드 만들기** → 프론트의 '단말기 연결' 화면에 8자리 코드 입력 (30분 안).
5. 라이브 배포는 토스 심사(매주 월 · 목) 후 VAN 대리점이 토스플레이스 파트너스에서 켜 줍니다. 단말기 재온보딩이 필요합니다.

### 알림톡
- 결제가 끝나면 **구매 완료** 알림이, 마지막 만료 시각 기준으로 **만료 예정** 알림(월간 · 3개월권 3일 전 · 1일 전, 15일권 1일 전, 1일권 2시간 전, 2시간권 20분 전)이 대기열에 들어갑니다. 이어 붙이거나 기간을 바꾸면 만료 알림은 자동으로 다시 계산됩니다.
- 발송 업체를 정하기 전에는 실제로 보내지 않고 **문구만 기록**합니다 (`ALIMTALK_PROVIDER` 를 비워 둔 상태). 문구는 `functions/_lib/notify.js` 의 `TEMPLATES` 에 있고, 카카오 템플릿 심사를 받은 문구와 똑같아야 합니다.
- 업체를 정하면: 템플릿 코드를 `ALIMTALK_TPL_PURCHASE` · `ALIMTALK_TPL_EXPIRE` 에, 발송 방식을 `ALIMTALK_PROVIDER` 에 넣습니다. 지금 들어 있는 방식은 `webhook`(`ALIMTALK_WEBHOOK_URL` 로 JSON 전달)뿐이고, 업체 전용 연결은 업체를 정한 뒤 `notify.js` 에 추가합니다.
- **5분마다 보내기**: Pages 에는 예약 실행이 없어 `workers/notify-cron` 을 별도 Worker 로 배포합니다 (Cloudflare → Workers & Pages → Create → Worker → 코드에 `index.js` 붙여 넣기 → Settings 에 `SITE_URL` · `CRON_KEY`(Secret) → Triggers 에 Cron `*/5 * * * *`). Worker 가 없으면 관리자 화면 알림톡 탭의 **지금 보내기**로 보냅니다.

## 5. 운영 상태 바꾸기

현재 `js/site-config.js` 의 `status.mode` 는 `"open"`(운영 중)입니다. 화면 맨 위의 운영 안내 띠는 2026-10-11에 요청에 따라 없앴습니다. 다시 필요하면 html을 새로 만들 때 되살릴 수 있습니다.

### 스페이스클라우드 정산 엑셀 일괄 가져오기

관리자 → 매출에서 호스트센터 **정산 완료**의 원본 XLSX를 선택합니다. 호스트센터에서 공간을 `소셜팩토리 건대 (초특가)`로 필터링하고 내려받습니다. 다운로드 개인정보 안내의 확인 버튼을 누르면 파일이 저장됩니다.

- 2026-10-24 실제 내려받은 HOST 정산내역의 머리글로 검증했습니다. 예약번호, 이용시작/종료일, 결제일시, 결제금액, 취소금액을 읽습니다. 수수료나 정산 지급 금액으로 매출을 역산하지 않습니다.
- 브라우저 안에서 XLSX를 읽고, 이름·전화번호·호스트 ID는 서버로 보내지 않습니다. 서버에는 필요한 날짜·예약번호·금액만 보냅니다.
- 미리보기 후 ‘위 내역을 매출에 반영’을 눌러야 저장합니다. 예약번호가 같은 파일은 한 번만 합산하며, 다른 지점·잘못된 금액·기존 기록과 다른 금액·수기 매출과의 중복 가능성은 저장을 막습니다. 환불 변경 파일은 자동으로 덮어쓰지 않고 확인이 필요하다고 알립니다.
- 금융 기록은 `spacecloud_sales`에 저장합니다. 기존 예약의 입퇴실 시간이나 예약 상태는 변경하지 않습니다. 캘린더에서 룸을 확인할 수 없으면 공간별 매출은 ‘기타’로, 여러 날짜 예약의 이용일 매출은 이용시작일에 귀속합니다.
- 정산 전 예약은 이 파일에 없습니다. 실시간 자동 수집이 아니라 **정산 엑셀 다운로드 → 관리자 파일 선택 → 미리보기 → 일괄 반영** 방식입니다. 원본 파일은 저장소에 포함하지 않습니다.
- 서버는 관리자 인증 후 필요한 테이블을 `CREATE TABLE IF NOT EXISTS`로 준비합니다. 신규 DB는 schema.sql에도 동일한 표가 있습니다.

### 정산 전 결제 수집과 결제일 매출

정산 예정은 `tools/spacecloud-collector` 크롬 확장 도구를 사용합니다. `/spacecloud-import-help.html`에서 설치·사용 방법과 다운로드를 제공합니다. 도구는 사용자가 클릭한 호스트센터 탭의 화면에 표시된 상세보기만 열고 읽습니다. 조회 조건을 유지해 첫 페이지부터 자동으로 이동하며, 소셜팩토리 결제내역만 JSON으로 저장합니다. 이 JSON과 정산 완료 XLSX를 동일한 관리자 파일 입력에서 가져올 수 있습니다.

- 비밀번호·인증 토큰·쿠키를 수집하거나 내부 API를 호출하지 않습니다. 원본 이름·전화번호는 파일에 넣지 않습니다. 도구 권한은 activeTab/scripting/storage이며, 호스트센터에서 사용자가 직접 실행해야 합니다. 설치와 실제 계정에서의 전 페이지 실행은 별도 사용자 확인이 필요합니다.
- 예약번호를 같은 금융 기록 키로 사용합니다. 정산 전 파일을 여러 번 가져오거나 같은 건이 정산 완료 엑셀에 포함돼도 합산은 한 번입니다. 금액이 바뀌면 기존의 확인 필요 차단을 유지합니다.
- 관리자 매출 기본 기준과 대시보드 이번 달 매출은 결제일 기준으로 변경했습니다. 미래 이용 예약도 실제 결제월에 합산됩니다. 매출 화면에서 이용일 기준으로 전환할 수 있습니다. 예약 시간표·이용시간 통계는 계속 이용일 기준입니다.
- 첫 페이지부터 최대 100페이지/5,000건을 읽습니다. 로그인 만료·구조 변경·페이지 중복·금액 읽기 실패 시 부분 파일을 저장하지 않습니다. 여러 날짜/자정을 넘는 예약은 추정하지 않고 중단합니다. 미정산 전액 취소는 결제금액과 취소금액을 함께 읽어 순매출 0원으로 계산합니다.
- 로컬 브라우저에서 실제 DOM 구조를 재현한 fixture로 수집→개인정보 제외→JSON 파일→관리자 미리보기/반영을 확인했습니다. 실제 크롬 확장 설치 후 전 페이지 수집 동작은 아직 검증 전입니다.

### 크롬 15분 자동 동기화 (2.0)

`/spacecloud-import-help.html`에 설치/연결 안내가 있습니다. 관리자 `/api/admin/spacecloud-sync`는 상태 조회·10분 일회용 코드 생성·키 해제를 담당합니다. `/api/spacecloud-sync`는 코드 교환과 동기화 전용 Bearer 키로만 접근하는 수집/오류 보고 API입니다. 키의 해시만 저장하며 180일 만료되고 관리자 키 교체 시 무효화됩니다. 일반 관리자 API를 호출할 권한은 부여하지 않습니다.

모든 관리자 로그인 사용자는 같은 D1 매출과 동기화 상태를 봅니다. 일반 홈페이지 회원 로그인은 관리자 권한이 아닙니다. 원래의 예약/주문·수동 가져오기는 유지합니다. 필요한 표/기존 ledger의 sync_seen 열은 인증된 연결 생성/수집 시 준비합니다.
